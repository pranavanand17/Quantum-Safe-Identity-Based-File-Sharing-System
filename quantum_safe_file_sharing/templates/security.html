ENVELOPE ENCRYPTION

From identity to protected file

Local prototype

This system uses identity-based access and key management combined with post-quantum cryptography. A student identity is mapped to an ML-KEM public key. ML-KEM is a key encapsulation mechanism, not an identity-based encryption algorithm.

USER IDENTITY→ PUBLIC KEY→ ML-KEM→ SHARED SECRET→ AES-256-GCM→ ENCRYPTED FILE

AES-256-GCM

Purpose: Encrypts the actual file with a random 256-bit key and an authentication tag that detects tampering.

ML-KEM

Purpose: Provides post-quantum key encapsulation so the file-encryption key can be recovered only with the recipient's private key.

Identity Mapping

Purpose: Associates a recipient identity (student ID) with their cryptographic public key in the local directory.

Authenticated Encryption

Purpose: AES-GCM refuses decryption if the ciphertext, nonce, or bound identity metadata has been modified.

Why Post-Quantum?

Sufficiently capable quantum computers could weaken widely used public-key algorithms such as RSA and elliptic-curve Diffie–Hellman. NIST standardized ML-KEM to support migration toward algorithms designed to remain secure against both classical and quantum attackers. This prototype does not claim the system is unhackable or “quantum proof”; it demonstrates a realistic envelope-encryption design using a maintained ML-KEM implementation.
